Why

macOS ships caffeinate at /usr/bin/caffeinate — a one-word way to keep the machine awake while a build, download, or long job runs. Linux and Windows have no equivalent with the same name and flags. This project brings the same command and flag semantics to both, so the muscle memory and the scripts carry over. On macOS this binary deliberately refuses to run, so it can never shadow the real one.

Same flags, same rules

The test suite enforces macOS-compatible CLI semantics: option parsing with combined flags and attached values, default -i behavior, the -u 5-second default, and -t/-w being ignored when a utility command is given.

Three ways to stop

Wrap a command and release when it exits, hold for a -t timeout, or watch a -w PID and let go when it terminates.

Native platform APIs

Platform sleep-prevention APIs are mapped to Linux and Windows equivalents. Physical power and sleep behavior still depends on host OS policy.

Usage

caffeinate [-disum] [-t timeout] [-w pid] [utility [argument ...]]

caffeinate prevents sleep while you run a command or until timeout/PID completion.

FlagWhat it does
-dprevent display sleep
-iprevent idle sleep
-mprevent disk-idle sleep (mapped to idle inhibition on Linux/Windows)
-sprevent system sleep (AC-power-only on Linux/Windows, best effort from host power status)
-udeclare user active (defaults to 5 seconds if -t is omitted)
-t <seconds>timeout
-w <pid>wait for PID to exit

Behavior matches macOS caffeinate rules: the default assertion is -i when no assertion flags are given, and both -t and -w are ignored when a utility command is provided.

Examples

caffeinate make test
caffeinate -disu -t 3600
caffeinate -w 12345
